- (decision) PARADIGM (user chose A): one generic ModuleFrame component + a declarative module descriptor (data, not code). Layout lives in exactly one place. Binds: all editor modules. Prevents: per-module bespoke layout drift (the OscillatorPanel/EffectPanel/inline split that caused 'cobbled-together'). Rejected B (base-class+subclass-per-module: layout re-enters subclasses, drift returns) and C (shared LookAndFeel only: doesn't fix root cause).
- (decision) GRID INVARIANT (adopted): the Rack owns all module placement on a fixed columns x rack-units grid (col width Wc, unit height Hu, uniform gutters). A module declares only its size class (S=1x1, M=2x1, L=2x2 cols x units) and occupies whole grid multiples; no module computes its own bounds. All resized() math lives solely in the rack layout engine = NFR1. Exact px (Wc/Hu/column count) are seed, to be pinned visually in the HTML mockup; starting point ~8 cols, Wc~=220, Hu~=150, gutter 10.
- (decision) KNOB-SIZE POLICY (user chose b, provisional): single uniform knob diameter across ALL size classes for now (max 'from one mold' + minimal). Revisit condition: if large modules look empty/unimportant, switch to per-size-class knob sizes (plan a: S->Small, M->Medium, L->Medium/Large).
- (decision) MODULE DESCRIPTOR (adopted): a module is data = { sizeClass, title, typeTag(Generator|Modulator|Processor), enableParam?, resetParams[], body[] }. body is an ordered list of BodyElement; ModuleFrame renders a uniform header (title/enable/reset) and flows the body into grid cells. Control kinds: Knob{paramId,label,displayTransform?}, Combo{paramId,label,items:static|dynamicProvider}, Toggle, Action{label,onClick}(PLUCK), FileAction{label,onChoose}(LOAD WAV).
- (decision) DISPLAYS (user chose A): a graphic display is just another BodyElement Display{component} occupying grid cells -> ONE layout mechanism, no separate custom-body path. Scope/Spectrum = a module whose body is one Display element; ADSR = 4 Knobs + 1 Display element. Existing WaveformDisplay/SpectrumDisplay/EnvelopeDisplay reused as the component. Rejected B (separate custom-body hatch: reintroduces a display special-case = the drift source).
- (decision) BINDING + STYLING (adopted): ModuleFrame creates & owns the APVTS attachments from the descriptor (no hand-wired *Attach members in the editor). One shared LookAndFeel (existing SynthyLookAndFeel) set by the rack; SynthySlider stays the standard knob for all knobs (rotary, right-click entry, shift-fine, wheel-step, mod ring). RT-safety/threading inherited from project-context.md, not re-decided.
- (decision) MODULATION RINGS (user chose a): a Knob body element carries an optional modTarget tag (Frequency|Amplitude|FilterCutoff); the rack offers lookup 'all knobs with modTarget==X'; a single editor timer reads the processor's LFO atomic + active target and sets matching knobs' rings. Keeps modulation declarative; rejected b (editor holds fixed knob refs = hand-wiring returns).
- (constraint) Inherited from project-context.md (binding, read-only): APVTS is the single source of truth; parameter IDs/order in Parameters.h never change; no allocation/locking on the audio thread; UI<->audio handoff via std::atomic; Synthy naming (.synthy, %AppData%/Synthy, class names) kept. UI redesign must not touch any of these.
- (change) Adversarial-review fixes: AD-2 adds fixed body-slot capacity per class (S=3,M=6,L=12) + build assertion (fixes Wavetable overflow). AD-4 adds Label{text} + Display{slots} elements, displayTransform as guarded {toDisplay,fromDisplay} pair (ratio<=0 => identity, no write-back), declarative dynamic-combo refresh via Action/FileAction.refreshes[], reset writes APVTS only. AD-5 dimming covers Display uniformly. AD-9 (new): cross-module coupling (Mix-Mode<->OSCs) only via shared APVTS; Mix-Mode is its own S module.

- (decision) AD-10: an ordered RackLayout model [{id,zone,position,visible}] is the single source of truth for placement. Binds rack + all Epic-4 features. Prevents each feature (show/hide, move, reorder, persist) keeping its own view of order/visibility. Show/hide/move/reorder mutate ONLY this model, then the rack re-runs the single layout() packing path (AD-2/NFR1 kept). Default zone+order move onto the descriptor; typeTag stays identity/colour and never changes on move.
- (decision) AD-11: custom layout persists as append-only standard APVTS params in .synthy. Binds preset serialization; extends inherited NFR3/format constraint. No kFormatVersion bump, no ID renamed/reordered; missing layout params => built-in default layout (old build / C# app); C# ignores until it mirrors. 'Reset layout' restores descriptor defaults, touches no audio param.
- (decision) AD-12: window width fixed (1520px); height auto-fits the VISIBLE rack. Binds editor<->rack sizing boundary. After any layout mutation the rack recomputes preferredHeight(width) from visible modules and the editor re-applies setSize; no user-drag/zoom resize (narrows the fixed-window non-goal to width-fixed, height-auto).
