topic: JASS Standalone UI — Unified 19" Rack Layout
updated: 2026-06-28T15:18
---

- (decision) Scope: UI-only redesign of the JASS standalone editor into a uniform 19-inch rack layout — every sound/filter/effect module shares one structure, controls, and displays, in ~3 standard sizes. No new audio features/modules. Motivation: current editor mixes OscillatorPanel + reused EffectPanel + many bespoke inline modules; previous attempt left an unsatisfying, inconsistent result.
- (decision) Working mode: Fast path. Stakes: personal/hobby -> concise PRD (~2-3 pages).
- (decision) Problem framing (user words): final UI looked cobbled-together / unprofessional, not 'from one mold'. Root cause: 3 parallel build mechanics (OscillatorPanel, reused EffectPanel, bespoke inline modules).
- (decision) Sizing model: standard size CLASSES combining rack-height AND footprint (width). Target ~3 classes. Visual style: minimal, space-saving, no external reference.
- (assumption) VST3 is a secondary surface: same editor should apply, but VST3 not yet tested by user -> treated as 'validate later', not a blocker.
- (decision) Confirmed by user: (1) size-class model = columns x rack-units, S=1x1<=3ctrls, M=2x1<=5ctrls, L=2x2 rich/display; (2) module anatomy = title+enable/bypass+reset + color/type tag + clear on/off state; (3) scope/spectrum/ADSR-curve are L modules in the rack; (4) header+keyboard stay as fixed chrome outside the grid; (5) fixed window ~1920x1200, resizable out of scope. Exact pixel constants + per-module class assignment deferred to architecture.
- (change) Reviewer fixes applied: FR3 control vocabulary extended to action/trigger buttons (PLUCK), file-action buttons (LOAD WAV) and dynamic combos (wavetable bank); FR4 adds per-knob display-value transform (played-frequency display); FR7 given concrete bypass rule (dimmed body, header lit). Low-severity soft-adjective finding accepted at personal stakes.
- (event) PRD finalized
