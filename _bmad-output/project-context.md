# Project Context for AI Agents

_This file contains critical rules and patterns that AI agents must follow when implementing code in this project. Focus on unobvious details that agents might otherwise miss._

---

## Technology Stack & Versions

- **Language:** C++20 (`CMAKE_CXX_STANDARD 20`, required). `_USE_MATH_DEFINES` is set (MSVC).
- **Framework:** JUCE (vendored as a git submodule under `JUCE/`, built via `add_subdirectory`). Modules in use: `juce_audio_utils`, `juce_dsp`. JUCE recommended config + warning flags are enabled — keep them clean.
- **Build:** CMake ≥ 3.22. Plugin formats: **Standalone + VST3**. Target/product name: `JASS` (`JASS.exe`); `IS_SYNTH`, `NEEDS_MIDI_INPUT`.
- **Compile defs:** `JUCE_WEB_BROWSER=0`, `JUCE_USE_CURL=0`, `JUCE_VST3_CAN_REPLACE_VST2=0`.
- **Toolchain:** Visual Studio 2022 (MSVC). Build via MSBuild from PowerShell; `cmake.exe` is NOT on PATH (full path lives in project memory).
- **Source layout:** `Source/{Audio, DSP, UI}` + `PluginProcessor.{h,cpp}`. New `.cpp` files MUST be added to `target_sources` in `CMakeLists.txt`; header-only DSP modules need no CMake change.

## Critical Implementation Rules

### Language & Framework Rules (C++ / JUCE)

- **APVTS is the single source of truth.** All parameters live in `juce::AudioProcessorValueTreeState`. Parameter IDs are defined ONLY in `Source/Audio/Parameters.h` (`Parameters::ID` namespace) and built in `Parameters::createLayout()`. Never hardcode an ID string elsewhere — reference `ID::xxx` (or the `ID::oscFreq(i)` helpers for indexed params).
- **Parameter versioning:** every `juce::ParameterID(ID::x, 1)` carries a version int. Add new params by appending; NEVER rename or renumber an existing ID (breaks saved state + preset interop).
- **DSP module convention:** each DSP block is a standalone class (mostly header-only in `Source/DSP/`) exposing `setSampleRate(double)` and a per-sample `process()`/`nextSample()`. Follow this shape for new modules; wire them into `SynthVoice` (and `prepareToPlay`).
- **Pitch model:** everything transposes relative to **C4 (MIDI note 60)**. FREQ knobs define the sound AT C4 (ratio 1.0 = drone/base). Apply `transposeRatio` per block in `renderNextBlock`, then restore the knob value afterwards (see `SynthVoice::renderNextBlock`).
- **Signal chain order (per voice) is intentional:** osc mix → noise/karplus/wavetable/sub → wavefolder → (amplitude LFO) → filter → envelope → distortion → bitcrusher → chorus → delay → reverb → clamp. The mono engine is widened to stereo only at the final master stage (`StereoWidth` in the processor). Preserve this ordering unless explicitly changing the architecture.
- **Use JUCE types/APIs** (`juce::String`, `juce::AudioBuffer<float>`, `std::atomic` for Audio↔UI handoff). `<JuceHeader.h>` is the umbrella include (generated by `juce_generate_juce_header`).

### Real-Time Audio & Threading Rules

- **The audio thread must never block or allocate.** No heap allocation, locks, file I/O, logging, or exceptions inside `processBlock` / `renderNextBlock` / any `process()`. Pre-allocate in `prepareToPlay`. Existing pattern: reuse scratch buffers across blocks (e.g. `arpHeldScratch` in the processor) instead of allocating per block.
- **Audio ↔ message/UI thread handoff goes through `std::atomic` only** (see `currentNoteRatio`, `lfoDisplayValue`, `heldNotesLo/Hi`, `liveDirty`). Never read/write plain shared members across threads. UI reads atomics; editor pushes values back via APVTS.
- **APVTS value-tree change callbacks are asynchronous.** Do NOT rely on `valueTreePropertyChanged` for anything order-sensitive. The "preset modified" flag is computed by value-comparing against `cleanSnapshot` precisely because the change-listener would race the "clear after load" (see `PluginProcessor.h` notes). Keep that approach.
- **`prepareToPlay` may be called repeatedly** (sample-rate/block-size changes). Propagate `sampleRate` to every DSP module there; don't assume 44100.
- **Auto-play drone** lives on its own MIDI channel (`kDroneChannel = 16`, `kDroneNote = 60`) so it never collides with played notes. Don't reuse channel 16 for user notes.
- **Clamp the final sample to [-1, 1]** at the end of the voice chain (already done) — keep new effects inside that guard.

### Preset & State Persistence Rules

- **⚠️ C# compatibility DROPPED (2026-07-18, user decision).** The `.synthy` format no longer needs to match the frozen C# Synthy `Preset` class — field names/enum strings may be renamed/restructured freely. Keep JASS's OWN back-compat instead: when renaming a field, read the old name as a fallback so existing `.synthy` presets + `LiveState` still load (see the LFO `Lfo*`→`Lfo1*` migration in `PresetIO.h`). Append-only APVTS-ID discipline still matters for saved *host/DAW* state but is no longer bound by C#. The C#-parity rules below are historical.
- **(historical) Two apps shared one preset format.** The C++ JASS and the (frozen) C# Synthy read/wrote the same `.synthy` JSON format; `Source/Audio/PresetIO.h` field names/enum strings matched the C# `Preset` class exactly. Superseded by the C#-drop above.
- **Enum strings = C# enum member names, no display spaces** (e.g. `"SoftClip"`, not `"Soft Clip"`). The `kXxx` `StringArray`s in `PresetIO.h` are canonical. UI display names may differ, but the persisted/interop string must be the canonical one. When adding a parameter with choices, add a matching canonical `StringArray`.
- **Shared on-disk location is deliberately still `Synthy`:** `%AppData%\Roaming\Synthy\` (presets in `\Presets`, live state in `LiveState.synthy`). Do NOT rename to "JASS" — it would break interop and lose users' state. (Only the product/display/CMake name is "JASS"; class names, the `.synthy` format, and the AppData folder intentionally keep the "Synthy" name.)
- **`LiveState.synthy` is auto-loaded on start and auto-saved on change by BOTH apps** (for A/B testing between C# and C++). It also persists `currentPresetName` and the "modified" flag.
- **`kFormatVersion = 1`.** If the schema changes, bump it and handle older versions on load — never silently misread.
- **Enable-split (rack-UI, 2026-07-01):** LFO / Noise / Filter / Distortion each got a dedicated APVTS enable bool (`lfoOn` / `noiseOn` / `filterOn` / `distortionOn`), appended (append-only, no ID renamed). `"Off"` was removed from those four choice combos. **The `.synthy` format is unchanged** — `"Off"` is still the on-disk disabled marker, mapped to/from the bool via `PresetIO::choiceOrOff` / `setChoiceOrOff` (no `kFormatVersion` bump). C# Synthy still owes the matching UI/model change (see `deferred-work.md`).
- **Enable-universalization (rack-UI, 2026-07-05, Story 2.4):** the three formerly always-on modules gained real enable bools too — `masterOn` / `adsrOn` / `mixModeOn`, appended (append-only), **default `true`**. Semantics: `masterOn` off ⇒ output muted (gated at the master `applyGain`); `adsrOn` off ⇒ envelope bypassed (constant gain, but `envelope.process()` still advances); `mixModeOn` off ⇒ OSCs summed additively regardless of `mixMode`. These are **new** `.synthy` fields (`MasterOn`/`AdsrOn`/`MixModeOn`) — no legacy "Off" string — so back-compat relies on **missing field ⇒ enabled** (the `jbool(..., rawB(...))` fallback in `PresetIO`). No `kFormatVersion` bump. C# Synthy owes matching fields (default on) — see `deferred-work.md`.
- **State save/load goes through `getStateInformation`/`setStateInformation`** (host) AND the shared `.synthy` files (cross-app). Keep both paths in sync when adding params.

### Code Quality, Style & Naming

- **Naming dualism (intentional):** the product/display/CMake name is **JASS**, but C++ class names keep the **Synthy** prefix (`SynthyProcessor`, `SynthySlider`), the preset format stays `.synthy`, and the AppData folder stays `Synthy`. Do not "fix" this inconsistency — it is deliberate (see Preset & State rules).
- **File naming:** PascalCase headers/sources matching the class (`BiquadFilter.h/.cpp`, `WavetableOscillator.h`). DSP modules live in `Source/DSP/`, audio engine in `Source/Audio/`, UI in `Source/UI/`. Header-only is the norm for small DSP modules.
- **Members:** `camelCase` members, `k`-prefixed `constexpr` constants (`kDroneChannel`, `kFormatVersion`), enum classes for types (`WaveformType`, `MixMode`, `LFOTarget`).
- **Comments explain WHY, not what.** The codebase favors substantial "why" comments on non-obvious decisions (e.g. octave-stack default tuning, async-callback race avoidance). Match this: when a value or approach is deliberate, document the reasoning inline.
- **Keep JUCE warning flags clean** — `juce_recommended_warning_flags` is enabled; don't introduce new warnings.
- **`JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR`** is used on owning classes (e.g. the processor) — keep it on new ones.

### Build & Workflow Rules

- **Build via MSBuild from PowerShell** (Visual Studio 2022). `cmake.exe` is NOT on PATH — use the full VS-bundled path when invoking CMake directly (stored in project memory).
- **After editing `CMakeLists.txt`** (e.g. adding a new `.cpp`), regenerate the build before building. Don't expect new sources to compile until they're in `target_sources`.
- **Test the plugin in REAPER v7.65** (installed DAW) for VST3; the Standalone target is the quickest smoke test.
- **Commit messages are written in German**, short and imperative, describing the user-facing change (see git history). Match that style.

### Critical Don't-Miss Rules

- **Never rename a parameter ID or change its index/order** in `Parameters.h` — it silently breaks saved host state and `.synthy` presets. Append new params at the end.
- **Never allocate / lock / log on the audio thread** (see Real-Time rules). This is the #1 source of audio glitches.
- **Don't rename "Synthy" → "JASS"** in class names, the `.synthy` format, or the AppData folder — interop and existing user state depend on it.
- **When adding a parameter, touch ALL the places:** `ID::` declaration → `createLayout()` → `PresetIO` read/write (+ canonical `StringArray` if it's a choice) → `SynthVoice`/DSP wiring → editor UI/attachment. Missing one leaves the param half-wired.
- **Keep new DSP inside the existing voice signal-chain order and the final `[-1,1]` clamp.** Widen to stereo only at the master `StereoWidth` stage.
- **`prepareToPlay` is the only safe place to (re)allocate / set sample rate** — and it can be called more than once.
