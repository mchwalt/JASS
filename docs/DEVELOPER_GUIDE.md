Everything you need to build, configure and extend JASS: prerequisites,
dependencies, build workflows, versioning/CI, every runtime and compile-time
configuration surface, repo conventions, and the known build gotchas.

## 1. Prerequisites & first build (Windows)

- **Visual Studio 2022** (C++ Desktop workload) — provides MSVC and a bundled
  CMake (`…\VS\2022\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe`
  if `cmake` is not on your PATH)
- **CMake ≥ 3.22**, **Git**
- No package manager, no Python, no other SDKs — [JUCE](Glossary.md#juce) is
  vendored as a Git [submodule](Glossary.md#submodule), all data dependencies
  are committed.

```powershell
git clone --recurse-submodules <repo-url> JASS
cd JASS
# if cloned without submodules:
git submodule update --init --recursive

cmake -B build -G "Visual Studio 17 2022"

& 'C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe' `
    build\JASS_Standalone.vcxproj /p:Configuration=Release /m
```

> Run builds from **PowerShell** — MSBuild slash arguments (`/m`,
> `/p:Configuration=…`) get mangled in Git Bash.

**Outputs**

| Artifact | Path |
|---|---|
| [Standalone](Glossary.md#standalone) | `build\JASS_artefacts\Release\Standalone\JASS.exe` |
| [VST3](Glossary.md#vst3) bundle | `build\JASS_artefacts\Release\VST3\JASS.vst3\` (no auto-install — copy to `C:\Program Files\Common Files\VST3\` manually) |
| Shared code lib | `build\JASS_artefacts\Release\JASS_SharedCode.lib` |
| Generated code | `build\JASS_artefacts\JuceLibraryCode\` (`JuceHeader.h`, `JASS_resources.rc`, `Info.txt`) |

**MSBuild targets** (generated by CMake): `JASS_Standalone`, `JASS_VST3`,
`JASS` (shared code), the five binary-data targets (`JASS_HelpEN`,
`JASS_HelpDE`, `JASS_DemoPresets`, `JASS_Wavetables`, `JASS_Samples`),
`JASS_All`.

**Linux** builds are exercised only by [CI](Glossary.md#ci) (see [§5](#5-ci--releases) for the
apt dependency list and the Ninja invocation). The project has never been
built locally on Linux — GCC gets JUCE's much stricter recommended warning set
(`-Wconversion -Wsign-conversion -Wfloat-equal …`) that MSVC's `/W4` does not.

**Verification model:** there are **no unit tests**. Verification = clean
build + running the app (and ears). The `tools/` measurement scripts and
one-off console harnesses (a test `.cpp` that includes a DSP header directly,
compiled with `cl.exe` from a VS dev prompt) are the way to isolate "user
hears nothing" from "code broken" for DSP work.

## 2. CMake anatomy (`CMakeLists.txt` — the only CMake file)

```cmake
if(NOT DEFINED JASS_CALVER)
    set(JASS_CALVER "2026.7.15")      # local/dev default; CI overrides per release
endif()
project(JASS VERSION ${JASS_CALVER})  # numeric CalVer, month unpadded
```

- **C++20** (`CMAKE_CXX_STANDARD 20`, required).
- `add_subdirectory(JUCE)` — the vendored submodule; no options set.
- `juce_add_plugin(JASS … COMPANY_NAME "JASSProject" PLUGIN_MANUFACTURER_CODE
  Synt PLUGIN_CODE Syn1 FORMATS Standalone VST3 PRODUCT_NAME "JASS" IS_SYNTH
  TRUE NEEDS_MIDI_INPUT TRUE)`. Deliberately absent:
  `COPY_PLUGIN_AFTER_BUILD` (no VST3 auto-install), icons, VST3 categories.
  **Never change the plugin codes** — existing DAW projects would lose the
  plugin.
- `target_sources` lists **10 `.cpp` files** — everything else in `Source/` is
  header-only. Adding a header-only DSP/spec module needs no CMake change;
  **adding a `.cpp` does**.
- **Five [`juce_add_binary_data`](Glossary.md#binary-data) targets**, each with its own `NAMESPACE` +
  `HEADER_NAME` (JUCE derives symbols from file *basenames* only, so EN/DE
  files with equal names would collide in one target):

  | Target | Namespace / header | Glob (all `CONFIGURE_DEPENDS`) |
  |---|---|---|
  | `JASS_HelpEN` | `HelpEN` / `HelpEN.h` | `Resources/EN/*.md` |
  | `JASS_HelpDE` | `HelpDE` / `HelpDE.h` | `Resources/DE/*.md` |
  | `JASS_DemoPresets` | `DemoPresets` / `DemoPresets.h` | `DemoPresets/*.jass` |
  | `JASS_Wavetables` | `Wavetables` / `Wavetables.h` | `Wavetables/*.wav` |
  | `JASS_Samples` | `Samples` / `Samples.h` | `Samples/*.wav` |

- Compile definitions: `JUCE_WEB_BROWSER=0`, `JUCE_USE_CURL=0`,
  `JUCE_VST3_CAN_REPLACE_VST2=0`, `_USE_MATH_DEFINES`.
- Linked JUCE modules: `juce_audio_utils`, `juce_dsp` (rest transitively),
  plus `juce_recommended_config_flags` / `juce_recommended_warning_flags`
  (MSVC: `/W4`, `/MP`, `/EHsc`, `/Ox` in Release — **no `/WX`, no `/utf-8`**;
  see gotcha [§10.5](#10-known-build-gotchas)).
- Nothing platform-conditional — Linux dependencies live in the CI workflow.

## 3. Dependencies

### 3.1 JUCE (the only third-party *code* dependency)

- Git submodule at `JUCE/`, url `https://github.com/juce-framework/JUCE.git`,
  pinned by commit (currently tag **9.0.0**). License: JUCE is dual-licensed
  (GPLv3 / commercial); JASS is GPLv3, which covers free JUCE use.
- **Update procedure:**

  ```powershell
  git -C JUCE fetch --tags
  git -C JUCE checkout -f <new-tag>
  cmake -B build          # regenerate
  # clean rebuild, run the app
  git add JUCE            # commit the new submodule pointer
  ```

  The JUCE working tree may show many files as dirty from EOL normalisation —
  that's noise; only the submodule pointer matters.

### 3.2 MIT [KEMAR](Glossary.md#kemar) [HRTF](Glossary.md#hrtf) data (committed, not fetched)

`Source/DSP/KemarHrir.h` (~66 KB) is **generated** by
`tools/gen_kemar_hrir.py` from the MIT KEMAR compact set (Bill Gardner & Keith
Martin, MIT Media Lab, 1994 — free with attribution; see the README's
*Third-party data* section). The header is not raw data: front-reference EQ,
synthesized low end and pink-weighted normalisation are applied offline
(rationale in the header comment). Table shape: 19 azimuths × 5°, 128 taps,
44.1 kHz, left+right.

To regenerate: download `compact.zip` from
`https://sound.media.mit.edu/resources/KEMAR/compact.zip`, then

```
python tools/gen_kemar_hrir.py --input <path>/compact/elev0 --output Source/DSP/KemarHrir.h
```

and **clean-rebuild** (the table size is compiled into the voice).

### 3.3 Embedded assets (all committed, all [seeded](Glossary.md#seeding) to [`%AppData%\JASS`](Glossary.md#appdata) on first run)

| Repo folder | Contents | Runtime role |
|---|---|---|
| `Resources/EN/`, `Resources/DE/` | one `.md` per module + per zone | online help (embedded only) |
| `DemoPresets/` | 7 `.jass` demo presets | seeded to `Presets\`; F1–F7 factory bank |
| `Wavetables/` | 5 example morph wavetables + `generate_wavetables.py` | seeded to `Wavetables\` |
| `Samples/` | 17 example WAVs + `generate_samples.py` | seeded to `Samples\`, pre-loaded into the SAMPLER SET combo |

Seeding is **idempotent** — an existing (possibly user-edited) file is never
overwritten. Consequence: after re-tuning a shipped demo preset you must
replace the AppData copy manually (or delete it and restart).

### 3.4 Python tooling (offline only — never part of the build)

All scripts are **standard-library only** (no numpy — project rule: measure
DSP with your own FFT/cmath):

| Script | Purpose |
|---|---|
| `tools/gen_kemar_hrir.py` | regenerate `KemarHrir.h` (see above) |
| `tools/measure_binaural_room.py` | measurement harness used to calibrate the ROOM detents |
| `Wavetables/generate_wavetables.py` | regenerate the example wavetables |
| `Samples/generate_samples.py` | regenerate the example samples |

## 4. Versioning

Two independent version numbers — don't conflate them:

1. **App version — [CalVer](Glossary.md#calver) `YYYY.MM.MICRO`** (e.g. `2026.07.15`).
   - Single source of truth: `JASS_CALVER` in `CMakeLists.txt` →
     `project(JASS VERSION …)` → JUCE's `ProjectInfo::versionString` /
     `JucePlugin_VersionString` → `JASS::versionString()`
     (`Source/Version.h`), which zero-pads the month for display.
   - **Releases never commit a version bump**: CI derives the CalVer per
     merge and passes `-DJASS_CALVER=…` at configure time. The local default
     in `CMakeLists.txt` only affects dev builds and is bumped occasionally to
     stay near the released number.
   - Shown in the header subtitle and the right-click title menu (which also
     shows the loaded preset's format version).
2. **Preset [`FormatVersion`](Glossary.md#formatversion)** — an integer schema contract
   (`PresetIO::kFormatVersion`, currently **6**). Bumped only for *value*
   [migrations](Glossary.md#migration); additive fields ride on missing⇒default. See
   [`JASS_Preset_Format.md`](JASS_Preset_Format.md).

## 5. CI & releases (`.github/workflows/release.yml`)

- **Trigger**: push to `main` (i.e. every PR merge), with `paths-ignore` for
  `**.md`, `docs/**`, `_bmad-output/**`, `.githooks/**` — docs-only merges
  release nothing. Plus manual `workflow_dispatch`.
- **Version job**: [`MICRO`](Glossary.md#micro)` = count of existing v<year>.<month>.* tags` — the
  tag list is the release source of truth (a deliberately rejected
  alternative was auto-committing bumps back to `main`). Outputs both the
  padded display CalVer and the unpadded CMake variant.
- **Build matrix**: Windows (default generator — deliberately *not* pinned to
  a VS version, runner images drift) and Linux (Ninja, Release). Linux apt
  deps: `libasound2-dev libjack-jackd2-dev libx11-dev libxext-dev
  libxrandr-dev libxinerama-dev libxcursor-dev libfreetype6-dev
  libfontconfig1-dev libcurl4-openssl-dev libwebkit2gtk-4.1-dev libgtk-3-dev
  ninja-build`. Both configure with `-DJASS_CALVER=<version>` and build
  `JASS_Standalone JASS_VST3`. The `build/` directory is cached keyed on
  `CMakeLists.txt` + `.gitmodules`.
- **Release job**: downloads both zips, `gh release create v<version>` with
  generated notes.
- **There is no PR-time CI** — breakage is discovered on `main`. Build before
  you open a PR.

## 6. Git workflow & repo conventions

- **Branch model**: work on `develop` (or a feature branch) → PR → `main`.
  **Never push to `main` directly** — enable the local guard once per clone:

  ```sh
  git config core.hooksPath .githooks
  ```

  (`.githooks/pre-push` blocks pushes to `main`; server-side branch
  protection isn't available on this private repo's plan.)
- **CHANGELOG** (`CHANGELOG.md`, Keep-a-Changelog style): collect notes under
  `## [Unreleased]`; promote them to a `## [YYYY.MM.MICRO]` section **as part
  of the PR** that will release them. Entries carry the reasoning, not just
  the what, and note "FormatVersion stays N / append-only" for additive
  features.
- **Commits**: English, Conventional-Commit style (`feat(sampler): …`,
  `docs(readme): …`, `chore(version): …`). **PR titles and descriptions are
  English too** — as is every artefact in this repo (see
  [`CLAUDE.md`](../CLAUDE.md) for the short version of the house rules).
- `.gitattributes`: `* text=auto`; `*.sh` and `.githooks/**` forced LF;
  `*.wav`, `*.jass`, images marked binary.
- `.gitignore` highlights: `/build/`, `.vs/`, `.claude/settings.local.json`,
  `/_bmad` (a junction to a globally installed BMAD core — the tracked BMAD
  *artifacts* live in `_bmad-output/`), `__pycache__/`.
- **`_bmad-output/`** is tracked on purpose: PRD, architecture spine
  (AD-1…AD-12), epics, and 30+ per-story implementation notes — the richest
  source for *why* the code is the way it is. `project-context.md` in there
  is partly stale (pre-rebrand); the `docs/` files supersede it where they
  conflict.

## 7. Runtime configuration surfaces

### 7.1 `%AppData%\Roaming\JASS\` (created on demand)

| Path | Purpose |
|---|---|
| `Presets\*.jass` | named presets (SAVE/LOAD dialogs default here) |
| [`LiveState.jass`](Glossary.md#livestate) | auto-saved working state (Standalone; loaded at startup, saved debounced ~1.5 s and on exit) |
| `Wavetables\*.wav` | seeded examples + user WAV imports (LOAD WAV opens here) |
| `Samples\*.wav` | seeded examples + user samples (SAMPLER LOAD **copies** files here so presets can re-resolve by name) |
| [`PresetBanks.json`](Glossary.md#preset-bank) | global F1–F12 assignments (array of preset names) |
| `ui-language.txt` | help language (`EN`/`DE`; written once changed) |
| `title-anim.txt` | 3-D title animation flag (`0` = off) |
| `PresetsBackup\` | originals backed up before format migration rewrites |
| `JASS.settings` | **JUCE standalone wrapper's own file** (not JASS code): audio/MIDI device setup, window position, its own plugin-state blob. On Linux: `~/.config/JASS/JASS.settings`. |

**Migration**: on first launch, if `%AppData%\JASS` doesn't exist and
`%AppData%\Synthy` (the pre-rename app) does, the whole tree is *copied*
across with `*.synthy` → `*.jass` renames; the old folder stays as a backup.
⚠️ `migrateLegacyAppData()` must remain the **first** AppData access at
startup — any earlier `jassFolder()` call creates the folder and permanently
suppresses the migration.

### 7.2 In-app configuration

| Surface | Persisted to |
|---|---|
| Help language combo (header) | `ui-language.txt` |
| Right-click on the title: version info, preset-format info, 3-D animation toggle | `title-anim.txt` |
| MODULES panel: show/hide, reorder, zone move, L/R alignment, Reset layout | [`rackLayout`](Glossary.md#racklayout) property on [`apvts.state`](Glossary.md#apvts) → LiveState/preset `RackLayout` |
| F1–F12 preset bank (single = load, double = assign) | `PresetBanks.json` |
| Audio/MIDI settings (standalone "Options" button — JUCE dialog): output device, sample rate, buffer, **MIDI input devices** | `JASS.settings` |

Window size is *not* user-configurable: width fixed 1920 px, height auto-fits
the visible rack, auto-downscale on small displays — with a floor of 1:1
physical pixels (`1.0 / display->scale`), because below that the rack stops
being readable. Rack height is therefore a budget; the MODULES panel shows
what the current module selection costs against it.

### 7.3 Test-reset

To simulate a fresh install: quit JASS, delete (or rename) `%AppData%\JASS`.
Seeding recreates presets/wavetables/samples on next start. Deleting only
`JASS.settings` resets window placement + audio/MIDI device selection.

## 9. Working on the code — practical workflow

1. **Branch** from `develop`; enable the pre-push hook.
2. Incremental builds via `build\JASS_Standalone.vcxproj` are fine for
   ordinary `.cpp` edits. Switch to **`/t:Rebuild`** whenever you touched a
   header-defined struct's size or a `*Specs.h` (see gotchas).
3. Before building: make sure `JASS.exe` isn't running
   (`Get-Process JASS`) — otherwise the link fails with LNK1104.
4. Verify in the running app (no unit tests). Parameter/spec default changes:
   press RESET in the app — the auto-loaded LiveState otherwise masks new
   defaults.
5. For VST3 testing: build `JASS_VST3.vcxproj`, copy the bundle to
   `C:\Program Files\Common Files\VST3\`, rescan in the DAW (REAPER is the
   reference host).
6. Update `CHANGELOG.md` (`Unreleased` → promote in the releasing PR), open
   the PR to `main`; the merge triggers the release pipeline.

## 10. Known build gotchas

1. **[ODR/ABI trap](Glossary.md#odr) — [clean rebuild](Glossary.md#clean-rebuild) after header struct-size changes.**
   Growing a struct that `SynthVoice` embeds by value (mod-slot arrays,
   `kNumPanGenerators`, `LiveModFeed`, `WaveformCapture`, the HRIR table, …)
   with an *incremental* build leaves TUs compiled against different layouts →
   heap corruption / `0xC0000005` at startup. Always `/t:Rebuild` after such
   changes. (A fresh CI checkout is immune — this bites only local
   incremental builds.)
2. **`*Specs.h` edits may not recompile `ModuleRegistry.cpp`/`PluginEditor.cpp`.**
   The spec headers funnel into very few TUs; dependency-tracking misses ship
   stale APVTS defaults (observed: an OSC default change that didn't take).
   Fix: delete the affected `.obj` (`build/JASS.dir/Release/…`) or clean-build
   — and verify default changes in the running app (RESET).
3. **New/removed embedded resources** (`.md` help, `.jass` demos, `.wav`
   assets): the globs are `CONFIGURE_DEPENDS`, but the binary-data targets are
   best rebuilt with `/t:Rebuild /nodeReuse:false`; a transient **LNK1236** on
   the first link after resource regeneration resolves on a second link pass.
   Deleting a shipped demo preset requires deleting the repo file **and**
   rebuilding (it's embedded) — seeding would otherwise resurrect it.
4. **LNK1104**: the app is still running and locking `JASS.exe` — close it
   first.
5. **Non-ASCII string literals**: the build does **not** use `/utf-8`; sources
   are UTF-8-without-BOM read in the ANSI codepage. Convention: keep literals
   ASCII, or wrap them (`juce::CharPointer_UTF8`, `juce::String::fromUTF8`,
   `\xNN` escapes). Do **not** add `/utf-8` — it would break the existing
   wrapped literals. German UI strings live in the runtime-loaded
   `Resources/DE/*.md` wherever possible, which sidesteps the issue.
6. **`JASS_resources.rc` goes stale after a version change.** JUCE's custom
   command for the `.rc` has no dependency on the regenerated version info, so
   the Windows file-properties version of `JASS.exe` can lag behind. Delete
   `build\JASS_artefacts\JuceLibraryCode\JASS_resources.rc` (or the whole
   `build/`) after changing `JASS_CALVER`. The in-app version updates
   correctly either way (it comes from `JuceHeader.h`).
7. **`-DJASS_CALVER=…` is sticky**: once passed at configure time it persists
   in `CMakeCache.txt` for that build tree until overridden or the cache is
   wiped.
8. **New `.cpp` files must be added to `target_sources`** — header-only code
   needs no CMake change.
9. **UI/layout edits sometimes don't take with incremental builds** (stale
   layout despite fresh timestamps) — when in doubt, `/t:Rebuild`.
10. **Test-window trap**: the [standalone](Glossary.md#standalone) restores its window size from
    `JASS.settings`; after design-height changes an old window can clip the
    new UI — delete the settings file when testing layout changes.
